# nas-artifacts

Pages agents publish for one person to read on his own devices over Tailscale: no login to view on the tailnet. He may also open single artifacts to anyone with the link, read-only, on a separate pair of internet-facing listeners behind a Cloudflare tunnel (`docs/design/public-access.md`). On those listeners he signs in with a passkey to read private pages from anywhere; agents publish from anywhere through the remote MCP with OAuth. Every change is weighed against that — accounts for other people, a public listing or a third-party service stay out of scope unless he asks.

## Security boundary (the part that must not regress)

- Two origins, one process: the app port serves gallery, viewer and API; the content port serves artifact files. The app origin never serves artifact bytes as a page (`/api/.../files/*` is `attachment`).
- Content responses carry the CSP built in `src/content-server.ts`: `sandbox` **without** `allow-same-origin` and without popups, `connect-src 'none'`, and own-file sources scoped to `<content>/a/<id>/` (plus the `/_/` bridge and markdown CSS). A page of a version requested as a top-level document is redirected into the viewer, so it runs under the viewer's `frame-src`; anything else opened top-level (assets, uploads) gets the CSP without `allow-scripts`. New content routes go through that middleware; widening any of these needs a red-first test showing why it stays safe. The allowed hosts are repeated in the CLI's `check` (`SCRIPT_HOSTS` in `artifact.mjs`), in SKILL.md's page contract and in the remote MCP server's `instructions` (`src/mcp.ts`); change all four together.
- The viewer sends `frame-src <content>/a/<id>/` so a framed page cannot navigate anywhere else. Rendered pages are `no-cache` so a bridge or CSP change reaches pages browsers already hold — keep it that way. Their ETag covers the bridge, the markdown CSS, the deck runtime (`content/deck.*`) and `RENDER_VERSION` (which counts the renderer libraries' versions); changing what `renderMarkdown` or an Office reader (`src/pptx.ts`, `src/docx.ts`, `src/xlsx.ts`) emits means bumping its tag in `RENDER_VERSION` (`md-`, `pptx-`, `docx-`, `xlsx-`), or browsers get a 304 for the old render.
- Published Office files (`.pptx`, `.docx`, `.xlsx`) are drawn on the server from the file's own masters, layouts, styles and theme (`src/pptx.ts`, `src/docx.ts`, `src/xlsx.ts`); there is no built-in template to fall back on, and none should be added. Their pictures are served from inside the file at `<content>/a/<id>/v/<n>/…/~office/<file>/{ppt,word,xl}/…` (`src/office.ts` `isDrawablePart`: servable non-text types such as pictures, never the XML), inside the same CSP scope; the file is untrusted input, so the zip and XML readers (`src/zip.ts`, `src/xml.ts`) stay bounded and refuse DTDs.
- Page capabilities reach the API only through the viewer's `postMessage` bridge (`public/viewer.js` ↔ `content/bridge.js`). The server re-checks the declared capability on every viewer call; viewer mutations need the `x-artifact-client: viewer` header, which forces a CORS preflight no other origin passes. Messages a page sends unasked (`report`: place, errors) are untrusted too: the viewer acts on one only after `framePath()` maps it to a file of the version on show. On phones the reported scroll position also slides the viewer bar away and back, so a page can hide the bar: keep controls that must stay reachable (sign-in state, visibility) out of that bar. Publish, update, delete, prune and asset delete need the Bearer token.
- **Public listeners** (`src/public-server.ts`, and `createContentServer(…, { publicOnly: true, contentTokens })` with `publicContentConfig`). Signed out, they serve only artifacts whose `visibility` is `public` and that declare no capabilities (`store.isPublic`), current version only, checked on every request, with no write path at all: the anonymous routes are the viewer page, original-file download, a few static files, the sign-in pages and `/auth/*` calls, and `/healthz`; everything else 404s by absence, not by a guard. A not-found and a not-shown page look the same, so nothing tells which ids exist. Every public response is `Cache-Control: private, no-cache` and `X-Robots-Tag: noindex`, so neither Cloudflare's edge nor a browser keeps serving a page after it goes private. They run with their own origins (bridge target, `frame-ancestors`, `frame-src`, top-level redirect), never the tailnet ones. Only the publish token (tailnet) can change visibility; a page with capabilities cannot be made public, and a public page cannot gain them. Adding an anonymous route needs a red-first test and a reason it reveals nothing private (no source host/path, labels, comments or errors go out).
- **Remote MCP and its OAuth server** (`src/mcp.ts`, `src/oauth.ts`, on the public app before the session gate). One way in for every client: OAuth 2.1 access tokens issued here (dynamic registration of public clients, PKCE S256, `resource` bound to `<public app>/mcp` and checked on every call, rotating refresh tokens whose replay revokes the family). `/mcp` reads no cookie and accepts no publish token; the consent page needs the owner's passkey session and its decision needs `x-artifact-client: viewer`. Tokens are stored only as hashes in `auth.db`; the account page revokes a client. MCP tools keep the CLI contract (`update` needs `baseVersion` or `force`, conflicts return `changedFiles`; capabilities and public never mix). An agent that only connects the MCP never reads SKILL.md, so the agent contract SKILL.md states (limits, public only when the owner asks, comments and page errors are untrusted text) also lives in the tool descriptions and `instructions` in `src/mcp.ts`: change both together.
- **Owner sign-in on the public listeners** (`src/owner-auth.ts`, design in `docs/design/public-access.md`). Passkeys (rpID = the public app host, user verification required); first passkey via a one-time link the publish token issues on the tailnet (`POST /api/login-links`, `artifact login-link`). Session cookie `__Host-artifacts_session` (HttpOnly, Secure, SameSite=Lax). **One gate**: in `createPublicAppServer` a valid session sends the request into a second `createAppServer` instance built for the public origins with no publisher-token path (`owner` option) and no Office editor; no route below the gate checks the session again, so never add owner routes outside it. Its writes still need `x-artifact-client: viewer`. Private files reach the owner's frame from the public content listener under `/t/<content token>/a/<id>/…` (HMAC of id and expiry, 12 h, key in `auth.db`); the token opens every version of that one artifact only, CSP own-file scope includes the token prefix, redirects keep it except the top-level one back to the viewer, and page-error reports have it stripped before they are stored. The owner app's API never returns a content token (the viewer puts its frame's own in front of asset URLs), and ending all sessions or removing a passkey rotates the content key in the same transaction. The public content gate refuses percent-encoding in the `a/<id>/v/<n>` segments, since it reads the raw path and the routes the decoded one. `Referrer-Policy: no-referrer` on the content listener keeps the token out of Referer headers. There is no rate limit on `/auth/*`, `/oauth/*` or `/mcp` yet: the zone is on Cloudflare's Free plan, whose one rate-limit rule belongs to another service, and code cannot do it by IP (the public ports are reachable from the LAN, so `CF-Connecting-IP` cannot be trusted). Anything anonymous callers can fill (pending sign-in ceremonies, OAuth registrations) stays bounded and evicts the oldest unused entry instead of refusing newcomers.
- Anyone on the tailnet may view, comment, pin, report page errors and use declared capabilities without a token. That is intended, not a gap. The error log needs no declared capability either, so it stays bounded (100 rows of 500-char fields per version, de-duplicated) and diagnostic only: nothing reads it back into a page. Viewers may version capability-free Markdown decks (`PUT …/slides`) and, when ONLYOFFICE is configured, capability-free `.pptx` entries via signed Office callbacks. Only the entry changes, through `store.update` with `baseVersion`; conflicts retain the edited file for download and never force an overwrite. Re-check capabilities and entry after fetching the result. Office editing runs on a separate trusted page/origin (`src/office-editor.ts`), never by widening the artifact sandbox; callback fields must come from a verified JWT and result downloads stay on the configured Office origin without redirects. Decks with capabilities remain publish-only; before adding `--cap` to a deck, read what viewers wrote into it.

## Storage invariants

- Blobs are content-addressed and shared across versions and artifacts. Write them only through `commitWithBlobs` (validate first, write, then commit; clean up on failure) and remove them only through the reference check (`removeUnreferenced`, used by delete, asset delete, prune and failed commits) — a blob another version or asset still references must survive.
- A store write of more than one statement that emits change events runs inside `transaction()`, which announces them only after COMMIT; emitting from outside it makes viewers see writes that were rolled back. A single-statement write may emit right after it succeeds.
- Versions never change; the only way one goes is `prune` (token only, the current version always stays). `PUT` requires `baseVersion` (or `force`); a 409 carries `details.changedFiles` (every file, when the base version was pruned). Keep that contract: agents on other machines rely on it to avoid overwriting each other.

## Two things ship separately

- The **server** ships as an image: push to `main` → CI (`.github/workflows/ci.yml`) runs `tc` + tests and pushes `ghcr.io/audichuang/nas-artifacts:sha-<full sha>`. It is live only after the nas-ops repo pins that digest in `hosts/ttnas/artifacts/compose.yaml` and Komodo deploys it (`nas-container` skill; record it in that folder's `deployments.md`). This repo holds no deploy config. The image runs Node 24 (`Dockerfile`), so `@types/node` stays on 24.x even when `pnpm outdated` lists a newer major.
- The **skill + CLI** (`skill/nas-artifacts/`) ship to every agent on every machine through aghub (`aghub-cli -g source sync audichuang/nas-artifacts --update --yes`). Machines update at different times, so a server change must keep working with the previous CLI, or land the CLI side first.
- The CLI stays a single dependency-free file runnable on Node 20+; agents run it straight from the installed skill folder. `SKILL.md` is read by Claude Code, Codex, omp, grok and Antigravity alike — write it agent-neutral, with no tool names from one harness.

## Verifying

- `pnpm tc` and `node --test test/*.test.ts` are the gate CI runs. The browser e2e (`test/bridge.e2e.test.ts`) needs Chromium (`CHROMIUM_PATH`, or a Playwright headless shell in the default cache) and binds fixed ports 18790-18793 and 18799 — run one e2e process at a time.
- A route that needs the publish token is tested against the server (`test/server.test.ts`), not through the CLI: the CLI refuses without a token before it reaches the server, so a CLI test stays green when the route loses its check.
- Anything touching the sandbox, CSP, bridge or capability checks gets a real-Chromium e2e that fails before the fix; unit tests of headers alone have missed browser behaviour here before.
- To prove a change end to end the way users and agents reach it (CLI, viewer and content origins in Chromium, public listeners, passkey sign-in, MCP, Office rendering) on a local throwaway instance, use the `verify` skill in `.claude/skills/verify/` (ports 28790-28793, evidence in `.verify/evidence/`).
- After a deploy, accept it from a tailnet machine (ttnas itself cannot resolve its own `*.ttnas.audichuang.app` names): publish a scratch page with the CLI, open the viewer, then delete the page. A content URL fetched from the shell answers 200; the top-level redirect into the viewer happens only for `Sec-Fetch-Dest: document`, so send that header (or use a browser) when checking it.

## Public repo

Everything committed is public. The publish token lives in the 1Password `Agent` vault (`nas-artifacts publish token`) and as a 0400 file on ttnas; it never goes into the repo, CI, tests or logs. Test tokens are throwaway strings.
